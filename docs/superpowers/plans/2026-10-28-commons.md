# Claude Commons Implementation Plan

Goal: Give a Claude Team organizer an operational private knowledge workspace.
Architecture: Vinext React UI, authenticated server routes, D1 durable records; Claude Messages API for grounded answers. No unsupported Claude OAuth or session-cookie scraping.
Tech stack: TypeScript, React, Cloudflare D1, native fetch.

Scope: Team Primary Owner organization exports and member-provided JSON/JSONL/text; preserve author/project attribution where supplied. Plain-text project knowledge can be imported separately. Attachments and complete project metadata are not inferred. Organizer aggregates multiple people's content; private deployment is not a multi-user permissions product.

Design: paper #f7f9fc, ink #172638, navy #173b55, teal #137d78, muted #6b7c8d, line #e2e8ef. Segoe UI for English/Thai. Left navigation, broad working surface, source-aware conversation rows. Empty states guide importing. No invented production statistics.

- [x] Import/retrieval core: tests for Claude JSON, Code JSONL, mixed sessions, invalid files, repeat-import identity, Thai retrieval, source filtering. Implement lib/knowledge.ts with bounded parsing and stable source IDs.
- [x] Persistence/API: db/schema.ts and app/api/workspace/route.ts. Every operation requires signed-in identity, owner-scoped rows, same-origin writes, input limits. Tests cover scope and CSRF helper; import is transactional and idempotent. Store normalized text, not original uploaded binary.
- [x] UI: app/page.tsx and globals.css. Overview, library detail, source import/preview, knowledge answer citations, task board and connector instructions. Source selection respected by retrieval. No-key mode returns clearly labeled search excerpts.
- [ ] Verification: node --test tests/*.test.ts, tsc --noEmit, migration generation, build, local API/browser checks, fresh review; publish private using Sites workflow.

Review focus: oversized files, unknown export shapes, imported instructions, missing API key, unauthenticated/cross-owner access. API failures must never produce a fabricated answer. D1 imports update existing conversations and replace their chunks atomically. Deleting an imported conversation cascades to its chunks and tasks and never touches Claude.

Ruling: User said start now and delegated platform choice; proceed without additional design approval. Team plan confirmed. Start with export ingestion, not Enterprise-only live sync. Retrieval uses multilingual keyword ranking with bounded context; no claim of fine-tuning or exhaustive recall. Automated sync, OTLP collection, full attachment parsing, and member RBAC remain documented future integrations.

Verification ledger: 7 unit tests pass; TypeScript passes; local integration passes anonymous/CSRF rejection, idempotent import, scoped retrieval, task transitions and delete cascade. Reviewer identified ID-less source collision; fixed with regression test. Browser inventory empty, so screenshot/interaction QA unavailable. Live Claude API not exercised (no credential).
